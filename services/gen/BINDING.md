# Validated mesh scale binding (B04)

Owner: Ani. The shared contract remains `.claude/contracts.md`: metres, +Y up,
-Z front, bottom-centre origin, and dimensions within 1 mm after export/reload.
This is a local library; the existing `/bind` HTTP route is still a stub. No
Worker, storage, generation, fit or embedding interfaces were changed.

**Software gate: PASS on synthetic fixtures. Real SF3D semantic orientation and
visual distortion review: BLOCKED_ON_B02.** Matching a supplied box does not
establish physical measurement accuracy, room fit or visual plausibility.

## API

```python
from app.binding import bind_glb, OrientationProfile

# Only use identity when the source's semantic axes were actually established.
profile = OrientationProfile(
    name="reviewed-source-axes", version="1",
    matrix=((1, 0, 0), (0, 1, 0), (0, 0, 1)),
    evidence="manual_review",
)
artifact = bind_glb(raw_bytes, {"w": 0.73, "h": 1.29, "d": 0.47},
                    profile, scope="authorized-user-or-public-catalog-scope")
bound_bytes = artifact.glb
report = artifact.report
```

`BoundArtifact` stores immutable GLB bytes and report JSON. Reading `.report`
returns a fresh dictionary. Invalid inputs raise `BindingError`; known unsupported
features raise its `UnsupportedMesh` subclass. No artifact is returned on failure.
The caller supplies authorized scope; this library does not authenticate users.

Reports contain raw/bound SHA-256, bound identity, target and reloaded dimensions,
per-axis numerical errors, bottom-centre errors, orientation and complete applied
instance matrices, scaling/distortion diagnostics, primitive/material/texture
counts, embedded-image hashes, versions and validation result.

## Implemented transform and validation

1. Parse the entire single static GLB scene. Traverse nested nodes with accumulated
   world transforms, including matrix/TRS, rotations, nonuniform scale and mirrors.
   Separate copies are made for each shared mesh instance and each material
   primitive. Load the original scene independently through trimesh and compare
   its full scene bounds with the traversed bounds.
2. Validate exactly `w`, `h`, `d`: real, finite, positive numbers in metres. Reject
   booleans, strings, missing values and guesses. Reject raw extents <=1e-8.
3. Apply the explicit source-world-to-project proper rotation. The orientation
   profile has a name, version, matrix and `synthetic_fixture` or `manual_review`
   evidence designation. It is a caller assertion, not an inferred semantic front.
   No SF3D profile is supplied. No PCA or axis guessing is used.
4. Compute oriented bounds and `scale = target / extent`. Subtract
   `[centreX, minY, centreZ]`, then apply that per-axis correction once. Bake the
   full world/orientation/binding transform into positions. Transform existing
   normals using the inverse transpose and renormalize. Missing normals are
   generated by area-weighted face sums; failures such as zero normal sums reject
   the asset. Reverse triangle winding for a mirrored instance.
5. Write actual GLB bytes with identity output nodes. Preserve visual JSON records
   and original embedded binary data directly instead of converting materials
   through trimesh's exporter. UV/color accessors, primitive material assignments,
   embedded image bytes, samplers, base color and PBR parameters remain unchanged.
   Nodes are flattened per primitive instance; source hierarchy is not retained.
6. Parse those exact bytes and independently reload them as a trimesh scene.
   Check finite vertices, valid indices, nonzero triangle areas, unit normals,
   identity nodes, retained primitive instances/topology/visual attributes,
   unchanged material/texture records and image hashes. Assert every dimension
   error <=0.001 m and minY/centreX/centreZ errors <=0.001 m. Float32 rounding that
   cannot meet tolerance is an error, never a reason to increase tolerance.

Downstream placement scale must remain 1. The GLB coordinates already represent
metres; `asset.extras` also records that interpretation. Software tolerance says
nothing about the accuracy of LiDAR or merchant dimensions.

## Supported subset and explicit limits

The current path accepts GLB 2.0 with one scene, one embedded binary buffer,
static triangle primitives and embedded still PNG/JPEG textures. Float positions,
normals, UVs and colors, unsigned indices, tightly packed or interleaved accessors,
multiple materials/primitives and shared mesh instances are supported.

It rejects external buffers/images, sparse/normalized accessors, extensions
(including compression), animation, skins, morph targets, unsupported attributes,
unreachable/cyclic/shared nodes, singular transforms and vertices unused by any
triangle. This avoids silently ignoring data or using invisible vertices for bounds.
Raw and exported GLB are each capped at 64 MiB; at most two million instanced
vertices, 1,024 mesh instances, depth 64 and 16 million pixels per texture.

**Tangents and normal maps are explicitly rejected.** Preservation of tangent
space under arbitrary nonuniform transforms is not proven by this implementation.
A generated asset containing either is unsupported; do not strip these fields or
claim a visual pass to bypass this check. Additional formats/features need a
focused preservation test and an intentional binder-version change.

This is a contract validator for the supported subset, not a complete Khronos
conformance validator. PBR rendering appearance on the actual client remains a
separate visual review even when all source material records and image bytes are
preserved. The scratch unlit projection used for synthetic review is not a PBR
renderer.

## Raw identity, double binding and selection

`raw_key(scope, image_sha256, model_revision, generation_settings)` hashes the
explicit authorized scope, source image and generator source revision. Settings
must include `weights_revision`, `secondary_weights`, `preprocess_revision`,
`dtype`, `seed`, `texture` and `remesh`; additional settings participate in the
hash. Supply the actual resolved values, including foreground/crop policy in the
preprocessing configuration. These are component-local helpers, not storage keys
or new shared contracts.

`bound_key(scope, raw_sha256, bbox_meters, orientation_profile)` includes exact
float64 target values (hex encoding, no rounded dimensions), the complete profile,
binder/exporter version and NumPy/trimesh versions. Different scopes, boxes,
profiles and versions produce different identities. Every binding starts from
immutable original bytes; two target boxes never mutate each other's artifacts.

An `ani_scale_binding` provenance marker is embedded in asset, scene and output
nodes. Receiving an already marked mesh raises; retrieve raw input instead.
Markers prevent accidental rebinding, not malicious provenance stripping or
rebinding through an external tool that removes all extras. Callers must retain
raw/bound identity separately and never substitute a bound blob into raw storage.

`GeneratedAsset(raw_glb, image_sha256)`, `SelectedProduct(object_id, image_sha256,
bbox_meters)` and `bind_selected(...)` connect the selected product's image and
box. The image hashes must match and only the selected product's box is passed to
the binder. Query A is not an input to this boundary. This guards the local seam;
it cannot prove that upstream callers supplied truthful image provenance.

## Distortion and publication

The report uses `r = max(scale) / min(scale)` with the plan's provisional labels:

- `r <= 1.25`: `eligible_for_visual_review`.
- `1.25 < r <= 1.5`: `review_required`.
- `r > 1.5`: `proxy_recommended` until axes/dimensions are checked.

These are diagnostic labels, not probabilities or measurement confidence. A
numerically valid output can be visibly distorted. All outputs retain
`publication_requires_visual_review: true`; the caller must honor the diagnostic.
The binder returns the validated candidate and does not publish it or fabricate a
proxy. A future caller may choose a clearly labeled dimensional proxy. No real
SF3D visual-distortion review has taken place.

## Reproduce software tests

Use the separate prepared CPython 3.11.9 environment; global Python is untouched.
Exact direct/transitive versions are pinned in `requirements-binding.txt`.

```powershell
$bindingRoot = Join-Path $env:TEMP 'ani-binding-b04'
$bindingPython = Join-Path $bindingRoot 'venv\Scripts\python.exe'
$env:PYTHONDONTWRITEBYTECODE = '1'
& $bindingPython -m pytest services/gen/tests/test_mesh_contract.py services/gen/tests/test_selection_binding.py services/gen/tests/test_mesh_cache.py -q -p no:cacheprovider --basetemp (Join-Path $bindingRoot ('tests-' + [guid]::NewGuid().ToString('N')))
python -m pip --isolated --python $bindingPython check
```

For a fresh isolated Python 3.11.9 environment, install only
`services/gen/requirements-binding.txt`. No GPU, model, Baseten access or network
is needed to run the tests after installing dependencies. Fixtures are generated
in memory by `tests/data/mesh/synthetic.py`, with obvious synthetic names and
embedded FRONT/UP/LEFT labels. See B04 evidence in the execution plan for actual
results, artifact paths/hashes and the still-blocked real-output gates.
